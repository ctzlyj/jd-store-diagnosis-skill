# EasyBI 京喜数据集（渠道补充口径）

用于补商智/黄金眼拿不到的**广告、CID、自然流量拆分**，以及纯京喜 C 店的货端/评价/售后指标。
它不是全店口径的替代品：先和商智/黄金眼对账，再决定怎么用。

## 1. 什么时候用

- 店铺是京喜 C 店，商智无权限或只有部门口径。
- 商智只能看到广告汇总，看不到广告 GMV / JDS / CID / 自然 GMV 的拆分。
- 需要按 SPU/SKU 看真实好评、售后、价格星级、信息分标识。
- 不要用它替代商智的全店成交、流量来源、搜索词；它是**京喜渠道**口径。

## 2. 已验证入口（2026-10-28）

数据源页（指标平台，分析型服务 tab）：

```text
https://easybi.jd.com/beta/#/datasource/13560?tab=27
```

该数据源下的数据集：

| 数据集 ID | 名称 | 用途 |
| --- | --- | --- |
| 1025136 | 京喜_通用数据集 | 成交/流量/广告/CID/评价/售后（主用） |
| 1096116 | 京喜_财务_损益 | 履约毛利、广告后毛利、NetGMV |
| 1097461 | 京喜C店升级京喜自营数据集 | C店升级进度，不用于经营诊断 |

先刷新会话（后台标签，不抢工作界面）：

```powershell
webcli browser <session> --window background open "https://easybi.jd.com/beta/#/datasource/13560?tab=27"
```

再读元数据：

```powershell
webcli easybi native --operation metadata --dataset 1025136 --keyword 广告 -f json
```

派生口径：

- 站内广告 GMV = `18900607 − 20833907`
- 自然 GMV = `18902197 − 站内广告 GMV − 19832758`
- ROI = 站内广告 GMV ÷ 广告消耗
- 广告占比 = 站内广告 GMV ÷ 18902197
- 费率 = 广告消耗 ÷ 18902197
- 广告 CVR = 18900608 ÷ 18901178
- CPA = 广告消耗 ÷ 18900608

## 4. 查询方式

### 4.1 原生命令（整部门，按店铺分组）

```powershell
webcli easybi native --operation query --dataset 1025136 `
  --start 2026-10-01 --end 2026-10-22 `
  --department 17603 `
  --dimension-group 7a43b98aa558f13279c5add3c0367bc3 `
  --exclude-shops 13496968 `
  --metrics "18902197,19832758,18900607,20833907,21988164" `
  --group-by shop --page-size 1000 -f json
```

要点：

- `--metrics` 的逗号列表**必须加引号**；PowerShell 会把它拆成多个参数，报 `UNVERIFIED_OR_AMBIGUOUS_METRIC:NaN`。
- 原生命令强制 `saler_dept_id_2`、C 店模式、`--exclude-shops`；不能指定「只查某几个店」。
- 只接受一页完整返回；`total` 大于 `page-size` 会报 `INCOMPLETE_NATIVE_RESULT`，不要拼接分页。
- 查询期间前台窗口变化会报 `WINDOW_FOCUS_CHANGED`，重试一次；仍失败就缩小指标数或改用 4.2。

### 4.2 指定店铺（页面上下文查询）

原生命令不支持 `shop in [...]`，用 `scripts/easybi_shop_query.py`：

```powershell
python -X utf8 scripts/easybi_shop_query.py `
  --shops 204560127,13490204 --department 17603 `
  --start 2026-10-01 --end 2026-10-22 `
  --metrics 18902197,19832758,18900607,20833907,21988164,15804346,15833672,15804356 `
  --session easybi13560 --out work/easybi-shops.json
```

脚本会在后台标签打开数据源页、复用页面登录态发 `POST /api/data-hub/data/query`，不读 Cookie、不落盘凭证。

## 5. 口径边界（必须写进报告）

1. **京喜渠道口径，不是全店**。纯京喜店可能等于全店；混合渠道 POP 店只是子集。
   2026-10-28 实测：东来臻选 10/1—22 京喜 GMV ¥21,836.34，与黄金眼部门口径一致；君凯卫浴 ¥34,414.31，也与部门口径一致；但两店的商智全店成交分别是 ¥21,836（东来无商智）和 ¥61,774.98（君凯含部门外），不能拿京喜数当全店。
2. **部门必须匹配**：`saler_dept_id_2` 用店铺实际所属二级部门；用错部门会漏店或串店。
3. **`--operators` 是人员范围，不是数据清洗**：加了运营人员过滤会漏掉归属其他人的订单，做全店汇总时不要加。
4. **广告消耗三套数**：`广告原始消耗`（21988164）、`广告现金消耗`（21811033）、商智「花费」不是同一个数；报告必须写明用的哪套。
5. **T+1**：先探最后一个有数日；当天数据不作为成交结论。
6. **CID/JDS 不要默认 0**：本期两店都是 0，但查询必须实取；缺字段写数据不足。
