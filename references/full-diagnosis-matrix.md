# 完整诊断矩阵（full mode，默认执行）

目标：一份诊断同时覆盖 ODA 诊断的全部维度 + 我们自己的看板能力，多多益善但不混口径。
规则：**板块不许删**；哪个源取不到，板块保留并写「数据不足 + 原因 + 影响哪个结论」。

## 0. 执行顺序

1. 判模式：商智权限有无 → 模式 A（商智+京准通）或模式 B（黄金眼+代理商智）。
2. EasyBI 1025136（京喜渠道）：店铺汇总、SPU 明细、星级/信息分分布、铺货节奏、货端质量。
3. 京麦：商品信息分、普惠到手价、实时订单（归因需要时）。
4. 商智/京准通/黄金眼按 SKILL.md 第 3、4 步采集。
5. 汇总成 report-input：全店口径一组、京喜渠道口径一组，两组并行呈现，不互相替代。

## 7. EasyBI 取数命令（scripts/easybi_shop_query.py）

```powershell
# 店铺汇总
python -X utf8 scripts/easybi_shop_query.py --shops 13490204 --department 17603 `
  --start 2026-10-01 --end 2026-10-22 --metrics "18902197,18900607,20833907,21988164" `
  --session easybi13560 --out work/easybi-shop.json --meta work/meta-1025136.json
# SPU TOP
... --metrics "18902197,15804345" --group-by spu_id --out work/easybi-spu.json --no-open
# 价格星级分布
... --metrics "15804348,18902197" --group-by jdr_sch_sku_price_star_d --out work/easybi-star.json --no-open
# 铺货节奏（首次上柜按日）
... --metrics "15804348" --group-by jdr_sch_sku_first_into_otc_tm --out work/easybi-launch.json --no-open
```

注意：`--metrics` 逗号列表必须加引号；单次 group-by 至多 2 个维度；结果必须完整翻页（脚本已内置，拒绝拼接脏页）。

## 8. 1108514（京喜SKU主体数据集）边界

元数据可读（734 字段），但 `businessScene=individual`，**原生 `/api/data-hub/data/query` 不支持**。它独有的原值字段（信息分原值、底线到手价、五星建议价、合伙人/陪跑/素材托管标识）目前只能走 EasyBI 页面探索；等价维度在 1025136 已覆盖大半（信息分标识、价格星级、店铺星级、真实好评、售后、首次上柜、在售标识、国补/甄选/IP/王牌）。POP 店的货端一律走京麦/商智。
