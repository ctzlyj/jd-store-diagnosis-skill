# POP 店铺诊断口径速查（唯一权威）

报告里每个指标都必须能对上本表。派生指标一律用脚本算，不心算；报告与 Excel 同源。
口径冲突时以本表为准；本表没写的，先在任务里验证，再补进来。

## 0. 三条总规则

1. **先定口径，再取数**：同一张表里不许混用「有效/下单」「全店/部门」「区间/日累加」。
2. **分母写清楚**：客单价、转化率、ROI、CPA 的分母各是什么，报告数据说明必须能复述。
3. **看不到就写数据不足**：缺哪个维度、为什么缺、影响哪个结论，逐项写；不删板块、不编数。

## 1. 交易类

| 指标 | 计算/字段 | 来源 | 口径要点 |
| --- | --- | --- | --- |
| 成交金额（有效口径） | 商智 `ordAmt`；日明细 `OrdAmt` 求和 | 商智 flow-core / 日明细 | 本文默认「成交金额」指它；已剔除取消/未付 |
| 成交金额（下单口径） | 商智 `orderAmt` | 商智 flow-core | 下单即计入，含后续取消/未付；只用于和有效口径对照 |
| 成交金额（部门口径） | 黄金眼 `DealAmt` | 黄金眼店铺看板 | 只统计主营二级部门，不是全店；类目同事对数用这个 |
| 成交件数 | 商智 `ordNum` / 日明细 `OrdNum`；黄金眼 `DealNum` | 商智 / 黄金眼 | 件数≠订单数；黄金眼 `ShopDealNum` 才是父单量 |
| 成交客户数 | 商智 `ordCustNum` | 商智 flow-core | 去重客户数；黄金眼没有这个字段 |
| 客单价（商智） | 成交金额 ÷ 成交客户数 | 派生 | 商智口径的分母是**客户数** |
| 客单价（黄金眼） | `CustPriceAvg` = 成交金额 ÷ 成交件数 | 黄金眼 | 黄金眼口径的分母是**件数**；两套客单价不可直接对比 |
| UV 价值 | 成交金额 ÷ 访客数 | 派生 | 前后期同口径；不要用下单口径算 |
| 成交转化率 | 成交客户数 ÷ 访客数（商智 `toOrdRate`） | 商智 | 广告 CVR 是另一套：广告父单 ÷ 点击 |
| 每百访客成交件数 | 成交件数 ÷ 访客数 × 100 | 派生 | 黄金眼没有客户数时，用它替代转化率做效率对比 |
| 退款/售后率 | 售后申请订单量 ÷ 订单量 | 商智/京麦售后 | 报告写明统计窗口；取不到写数据不足 |

## 2. 流量类

| 指标 | 计算/字段 | 来源 | 口径要点 |
| --- | --- | --- | --- |
| 访客数（区间） | 商智 `uv`；黄金眼 `SkuUV` | 商智 / 黄金眼 | 区间去重值，做环比用这个 |
| 访客数（日累加） | 日明细 `UV` 求和 | 商智日明细 | 只用于画分日趋势；零成交日可能缺行，累加会低估，不能当区间值 |
| 浏览量 | 商智 `pv`；黄金眼 `SkuPV` | 商智 / 黄金眼 | 与访客同口径取 |
| 商详 UV | 商智 `goodsVisitorNum`；黄金眼 `SkuUV` | 商智 / 黄金眼 | 商品访客，不是店铺访客 |
| 来源页浏览量 | flowSource `browse` | 商智 | 是浏览量口径，不是 UV；渠道转化率按平台字段，别自己拿成交÷浏览硬算 |
| 店内流转占比 | `inshop-rank` 的 `uvPercent` | 商智 | 看进店落点，不参与成交口径 |
| 新/老访客 | `newuv` / `olduv` | 商智 flow-core | 老客下滑要结合复购和召回动作看 |

## 3. 广告类

| 指标 | 计算/字段 | 来源 | 口径要点 |
| --- | --- | --- | --- |
| 花费 | 商智 `Cost`；京准通 `cost` | 商智 / 京准通 | 商智不区分红包（虚拟金）与现金；判断亏不亏前先核对京准通财务红包明细 |
| 展现 / 点击 | `Impressions` / `Clicks` | 商智 / 京准通 | 两端口径可能有差异，报告注明用的哪端 |
| CTR | 点击 ÷ 展现 | 派生 | 分品类 CTR 按三级类目实取，不用全店值近似 |
| CPC | 花费 ÷ 点击 | 派生 | 出价参考用普惠到手价，不用京东价 |
| 广告成交金额（有效） | 商智 `TotalOrderSum` | 商智汇总 | 与花费同窗口的有效成交 |
| 广告成交金额（下单） | 产品线 `orderSum` | 商智产品线明细 | 下单口径，不能和有效口径的 ROI 直接比 |
| 广告订单 | `TotalOrderCnt`（有效）/ `orderCnt`（下单） | 商智 | 分子分母同口径 |
| ROI（有效） | 有效广告成交金额 ÷ 花费 | 派生 | 报告主结论用这个 |
| ROI（下单） | 下单金额 ÷ 花费 | 派生 | 只作产品线内部参考，标注口径 |
| CPA | 花费 ÷ 有效广告订单数 | 派生 | 与客单价对比，看广告成本占客单比例 |
| 广告 CVR | 广告父单 ÷ 点击 | 派生 | 不是全店转化率 |
| 广告占比 | 广告成交金额 ÷ 全店成交金额 | 派生 | 分子分母都写清有效/下单 |
| 费率 | 花费 ÷ 全店成交金额 | 派生 | 判断投放是否过重 |
| 京东价 / 普惠到手价 | `jdPrice` / `perfectArrivalPrice` | 京麦营销价格管理 | 定价、出价、盈亏线一律用到手价；京东价只是展示价 |

## 4. 商品与货端质量

| 指标 | 计算/字段 | 来源 | 口径要点 |
| --- | --- | --- | --- |
| 有成交 SPU / SKU | 成交明细去重 | 商智 / 黄金眼 | 黄金眼 `DealSpuNum` / `DealSkuNum` |
| 动销率 | 有成交 SPU ÷ 在架 SPU | 商智 + 商品列表 | 分子分母都要「在架」口径 |
| TOP1 / TOP5 集中度 | TOP1（或前5）成交 ÷ 全店成交 | 派生 | 判断单 SPU 依赖；分子分母同源 |
| 商品信息分 | 平台「信息分」字段 | 京麦商品信息分 | <90 为不达标；空值单独计数，分母剔除空值 |
| 价格星级 | 平台「价格星级」字段 | 京麦/商智（有则取） | NULL 单独一行；低星给调价/下架建议，阈值按平台当期规则 |
| 店铺星级 | 平台「店铺星级」字段 | 京麦商家体验 | 阈值按平台当期规则，报告写明来源，不套别的店标准 |
| 累计好评率（真实口径） | (好评数 − AI评) ÷ (总评数 − AI评) | 商智评价 | 全店维度先分别加总分子分母再相除，禁止逐 SPU 相除后平均；后台无 AI 评字段时用展示口径并注明 |
| 售后率 | 售后申请订单 ÷ 订单 | 商智/京麦售后 | 与退款率区分：申请≠完成退款 |

## 5. 时间口径

- **T+1**：商智/黄金眼默认 T+1；取数前先探最后一个有数日，不要假设 T-1 恒可查。
- **同期对比**：部分月统一「本月 1 日—N 日 vs 上月 1 日—N 日」，天数相同；不与整月直接比。
- **不完全月月化**：必须比整月时，用「本月日均 ÷ 上月日均 − 1」，正文标注「X 月为不完全月（N 天）」。
- **大促/异常日**：单日峰值、活动日单列，不混进日均结论；剔除异常值时要写明剔除前后两个数。
- **实时 vs 快照**：回答「今天/刚才」用京麦订单实时接口；商智快照只作 T+1 复盘。

## 6. 数据源分工

| 数据 | 首选 | 降级 |
| --- | --- | --- |
| 订单/商品/价格 | 京麦 CLI（jdo-cli） | 商智页面接口 → 实时订单页 |
| 交易/流量/商品/行业/搜索词 | 商智 | 黄金眼 + 代理旧商智（模式 B） |
| 广告计划/单元/关键词/行业 | 京准通 | 商智广告汇总（只有产品线，无计划明细） |
| 部门口径成交 | 黄金眼店铺看板 | — |
| 货端质量（信息分/星级/评价/售后） | 京麦商品/体验后台 | 商智评价/售后；取不到写数据不足 |

## 7. 常见混用错误（交付前逐条自查）

1. 把「下单金额」当「成交金额」讲增长。
2. 商智客单价（÷客户数）和黄金眼客单价（÷件数）放同一张表比。
3. 全店口径和部门口径混在一张环比表里。
4. 用日累加访客当区间访客，零成交日缺行导致低估。
5. 广告有效 ROI 和下单 ROI 互相除。
6. 广告花费把红包当现金，得出「亏损」结论。
7. 用京东价算盈亏线/出价，不用普惠到手价。
8. 商智 cid2 和京准通 cid3 当同一套类目 ID。
9. 部分月直接和整月比环比。
10. 好评率逐 SPU 相除再平均，或没剔 AI 评。
11. 拿商智 T+1 快照解释「今天」的成交。
12. 报告里出现「~」区间（JoySpace 会渲染成删除线），统一用「—」。
