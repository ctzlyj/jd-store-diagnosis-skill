# 京东京准通「稳赚计划」机制、字段口径与提前验价用法

适用：POP 店铺稳赚计划（单品稳赚 / 新品稳赚 / 全店稳赚）的诊断与投放建议。
两类信息严格分开标注：**【官方】= 白皮书原文**；**【推断】= 本地样本观察，需实测验证**。

## 〇、权威来源与抓取方式

官方白皮书：京准通商学院《「稳赚计划」5.0白皮书——100%保收益》，releaseDate 2026-09-23。
页面 `https://jzt.jd.com/school/course/detail?contentId=19372` 是 CSR，直接抓 HTML 只得到「网站加载中…」。
正文走 CMS 接口（匿名可读，无需登录态）：

```
GET https://jzt-api.jd.com/cms/content?contentId=<contentId>
```

返回 `data.txt` 是 Slate 富文本 JSON 字符串，`type=p` 取 `children[].text`，`type=img` 取 `url`。
参数名必须是 `contentId`（传 `id` 报 `code:600 需要id参数`）；该端点只支持 GET。
同页其他数据源：`cms/content/button/list`（POST）、`cms/recommendContentList`、`cms/contentList`。
**结论：京准通商学院任一课程正文都可以用这个方式离线取全文再做规则比对，不必开浏览器。**

## 一、【官方】白皮书核心规则

### 1. 参与资格（商品池实时刷新，商家维度为定向邀约）

| 类型 | 条件 |
|---|---|
| 潜力品（常规稳赚） | 近 30 天订单销量 ≥5 单、累计好评 ≥3 个、价格星级 ≥3 星（俗称 533） |
| 新品稳赚 | SPU 下任一新品 SKU 累计好评 ≥1、价格星级 ≥3 星、在标天数 ≤20 天（绿标/黑标），享 14 天效果保障 |
| 成熟品牌商品 | 533 且近 6 个月 SPU 下 SKU 均未投放广告 |
| 全店稳赚 | 入驻京准通 180 天内 POP 新商（非 O2O、非采销虚拟金、非自营），店内至少 1 个 SKU 达 533，且不同时投放其他产品线或全站营销新品&单品计划 |

### 2. 账户与计划设置（需同时满足，否则不赔）

- 账户限时消耗 **99 元** 即享 100% 成本保效赔付；新商福利弹窗口径降至 **83 元/7 天**（日均 11.86 达标，2026-09-29 实测观察）。
- 仅支持**目标成交投产比**出价方式，不能切换出价方式，不支持一键起量；自动暂停/自动降预算/自动降出价等自动化规则自动失效。
- **目标成交投产比设置值需 ≤「稳赚计划投产比最高建议值」**（QA 复述为「投产比设置需低于稳赚投产比建议值」）。
- 活动期内每日最多修改目标投产比 **3 次**。
- 计划需保持投放 **7 天以上**且持续投放，不可暂停或删除；退出/停止后进入 **7 日冷冻期**。
- 保障以 **SPU 粒度**生效，同 SPU 下非新品标商品同样享受。

### 3. 周期与赔付发放

- **28 天为一个投放周期**，期满需重新创建计划；资格按周期刷新，仍是邀约制。
- **每 7 天赔付一次，T+2 自动核算（第 9 天到账，以实际为准）。**
- 未发放赔付的原因：投产比符合预期，或**计划消耗不满足消耗门槛**。
- 赔付为**站内红包**，与现金 1:1 消耗，**有效期 30 天**，可用于新快车/全站营销/京准调研/门店推广。
- 查看路径：京准通首页-财务账户-财务管理-红包-查看详情；计划侧看【稳赚保】标签。

### 4. 赔付公式（白皮书原文）

```
保障金额 = 现金消耗 − 交易额 / (100% × 汇总目标投产比)
汇总目标投产比 = 总交易额 / 预期消耗金额
预期消耗金额 = Σ( 时段交易额_i / 该时段目标投产比_i )
```

白皮书算例：消耗 500、交易额 3000（1000@ROI10 + 2000@ROI20）→ 预期消耗 200 → 汇总目标 ROI 15 → 实际 6 < 15 → 赔付 500 − 200 = 300。

**由公式直接推出的经营含义（数学恒等，非猜测）：**
保障生效时，`净广告成本 = 现金消耗 − 保障金额 = Σ(时段GMV_i / 目标ROI_i)`，
即 **有效广告费率 = 1 / 目标投产比**，与系统实际花了多少钱无关。
所以「100% 保 ROI」保的是**广告费率上限**，不是「保不亏」：

> **只有当商品毛利率 > 1 / 可享保障的最高目标 ROI 时，稳赚才是「保赚」；否则它保的是「亏损上限」。**

同时必须提醒商家：赔付是 30 天有效的站内红包，**只有持续投放才等价于现金**；停投等于放弃已产生的赔付价值。

**全店稳赚切换的经济账（2026-09-29 核算）**：目标投产比 > 保本线（1/毛利率）时，赔付兜底后净广告成本 = GMV/目标 < GMV/保本线 → 数学上是「免费保险」，**预算只控制放量、不控制风险**。例：实锁目标 3.1 → 需毛利率 >32.3% 才保本；3.2 → >31.3%。切换前用 rt=80/probe 实时核验实锁目标与保本线的距离。

### 5. 【官方】建议投产比是怎么定出来的

> 「系统会参考**商品历史数据**，并参考**商品所在价格带与三级类目的行业平均投产数据**后动态调整推荐投产比。」

实时动态 ROI：首建计划或连续 7 天投放积累数据、实际达成目标投产，**每 7 天刷新一次建议值**；新品稳赚达成 533 后标识切换为「稳赚」，「有机会按系统建议**上调** ROI 保障」。
→ 稳定达成目标 ROI 会让下一周期的保障线上移，广告费率进一步下降，存在**阶梯复利**。

### 6. 【官方】关键词与稳赚的关系（重要纠偏）

- 5.0 升级 3：「支持快车更多场景投放稳赚，以**关键词 tROI 出价**叠加 100% 成本保效」。
- QA：**「稳赚关键词智投模式」与「稳赚常规品模式」互斥**，且标注【即将上线】。
- 关键词智投 = 系统智能推荐精选词包，**商家只能在系统推荐范围内添加和修改**。

→ 当前阶段**无法自行加词来抬高稳赚 ROI**；稳赚只能设日预算与目标投产比。
关键词准备工作的正确定位：(a) 等关键词智投上线后从系统词包里快速取舍的候选池；(b) 单品稳赚之外并行的独立快车计划（注意「全店稳赚」明确不可同时投其他产品线，单品稳赚无此表述，仍以账户实际校验为准）。

### 7. 其他官方口径

- 订单统计：同快车-全站智能推广，**广告撬动的直接 + 间接订单**（口径比点击归因宽，利于达成目标 ROI）。
- 同时满足常规稳赚与新商全店稳赚：有潜力款 → 潜力款投单品稳赚 + 另建全店稳赚；无潜力款 → 先投全店稳赚，再筛转化效率优的品投单品稳赚。

## 二、接口字段 ↔ 白皮书规则的对应

`POST /dspad/bidding/suggest` 的 `swaBiddingSuggestList[]` 每个 SPU 返回：

| 字段 | 含义 | 依据 |
|---|---|---|
| `recommendBidList[].price` | 三档**系统建议目标投产比**（level 1/2/3，`selectFlag=true` 的是「荐」档）。**不是 CPC 点击出价。** | 前端传入目标投产比编辑器 |
| `topPriceTroi` | 前端参与校验用的**可填上限**（「投产比需≤X 可参与稳赚」）。是输入框边界。 | 前端校验逻辑 |
| `refundLimitPrice` | **【推断】即白皮书所说的「稳赚计划投产比最高建议值」**，也就是**享受赔付保障要求的目标 ROI 上限** | 见下 |
| `costThreshold`（`/dspad/sure/win/spu/cost/threshold`） | **每轮（7 天）累计消耗门槛**，低于它不发赔付 | 白皮书「计划消耗不满足消耗门槛」 |
| `bottomPrice` | 0.01，下限占位 | — |

### `refundLimitPrice` 的推断链（转述时必须保留「推断」二字）

1. 本样本 **30/30 个 SPU** 满足 `refundLimitPrice == max(recommendBidList[].price)`，即恒等于第三档（最高）建议值。
2. 白皮书设置要求写明：「目标成交投产比设置值需 ≤ 稳赚计划投产比**最高建议值**」。
3. 字段名直译即「赔付限制值」。
4. 每个样本都有 `refundLimitPrice < topPriceTroi`（例：1.4 < 2.5、2.1 < 2.9）。

→ **【推断】`topPriceTroi` 只是输入框能填到的上限，`refundLimitPrice` 才是「填到多少还能享受赔付」的线。把目标 ROI 设到 `topPriceTroi` 很可能填得进去却丧失保障资格。**
→ 给商家的稳妥建议：**目标投产比设为 `refundLimitPrice`（= 最高建议档），不要设到 `topPriceTroi`。**
→ 零成本验证方式：在创建页把目标 ROI 填到 `topPriceTroi` 观察是否仍出现【稳赚保】标签/保障提示，再改回（每日可改 3 次）；或第 9 天核对红包到账。

## 三、本地样本观察（两店 30 SPU，同日截面，脱敏）

- **同一价格 + 同一三级类目的商品，跨店返回完全相同的 `topPriceTroi` / `refundLimitPrice` / `costThreshold`。**
  这与白皮书「价格带 + 三级类目行业平均投产」口径吻合；对**零成交、零广告历史**的品，商品历史数据的影响接近于 0。
- 样本自然分成两簇，簇内价格-保障线单调，簇间同价不同值 → 即三级类目不同：
  - 类目甲（本样本 12 品）：价格 ≤40.8 → 保障线 1.4；41.8~56.8 → 1.6；70.8 → 1.7；77.8 → 1.8；85.8 → 1.9
  - 类目乙（本样本 5 品）：14.8 → 1.4；24.8 → 1.6；33.8 → 1.7
- **存在清晰的跳档临界价**：类目甲在 40.8 与 41.8 之间保障线由 1.4 跳到 1.6，
  对应有效广告费率由 1/1.4 = 71.4% 降到 1/1.6 = 62.5%，**1 元定价差 ≈ 8.9 个点的保底广告费率**。
- 第一档建议值在 30/30 样本中恒为 **1.1**（常数，无个性化信息量）；真正随商品变化的是第 2、3 档。
- `costThreshold ≈ 2.0~2.5 × (价格 / refundLimitPrice)`，粗略等于「按保障 ROI 跑出约 2~2.5 单 GMV 所需的消耗」。已获资格的品系数更高（约 2.8~3.7×）。**仅为本样本回归观察，不是公式。**
- 已获资格 vs 同类目同价位未获资格的品对比（当日截面）：资格品 `topPriceTroi` **下降**、`costThreshold` **上升**；其中成交较好的那个 `refundLimitPrice` 高于同价位无成交品（1.6~1.9 → 2.1）。
  → 【推断】未获资格品的 `topPriceTroi` 更像「类目价格带的理论上限」，获资格后才收敛为该商品的实际可填上限。
- 样本中 30/30 商品 `stars=4`（价格星级已达标），绝大多数 `saleVolumeStr=0`，即**卡资格的唯一短板通常是「近 30 天 ≥5 单」**。

### 3b.【已验证-本地】cap 与门槛的决定因子（2026-09-29 五店 69 SPU 修正）

**⚠️ 修正旧观察**：上文「同款同价跨店返回完全相同」与「costThreshold≈2.0~2.5×价格/refundLimitPrice」两个旧结论已被更大样本修正，以下为准：

- **门槛公式**：`costThreshold ≈ 5 × 京东价 / cap(topPriceTroi)`，60 SPU 中位误差 1.6%。与白皮书「消耗门槛=预测商品成交 5 单所需消耗」互相咬合 → **topPriceTroi 就是系统给该 SPU 在稳赚流量下预测可兜底的投产比**，门槛按 5 单 GMV 反推消耗。推论：cap 上升 → 门槛同步下降，双重受益。
- **公式例外（待验证）**：高客单样本不符（338 元 SPU 按公式应得 ~422，实际 210）；零销量 SPU 门槛一律 **7（保底地板值，与公式脱钩）**。
- **价格是最强杠杆**：同品异价 22.8 元→cap 3.9 vs 14.8 元→2.1；指甲类 cap~价格 r=0.70~0.90。
- **商品线决定基线**：修眉「收纳包」线 5 个 SPU 不论价格全部 2.1 地板（14.8–33.8 元）；指甲刀零销量品全部 ≥3.0。
- **真实成交锚定 cap（关键新证据，修正「跨店同价同 cap」）**：相机款同货同价跨店——有销量（100+）的店 cap **2.7** vs 零销量店 cap **3.3**。有真实转化数据的 SPU 被锚得更低，零销量走乐观先验；旧「跨店同款同价 cap 相同」的样本疑为零销量对零销量。**含义：有成交 SPU 的 cap 上移空间反而大**——稳赚+关键词注入更好证据 → 下轮刷新上移、门槛下降；差证据反向拉低（双向变化，方向由新证据 vs 旧锚点质量决定，待更多样本）。

## 四、提前验价：把接口变成选品与定价武器

核心事实：`bidding/suggest` + `cost/threshold` 对**尚未获得稳赚资格的 SPU 同样返回**保障线与门槛。
别人要等通栏弹窗才看得到一个品的数字，我们可以一次拿到全店每个 SPU 的「未来保障线 + 入场门槛」。

### 用法 1：全店保障线地图（每周跑一次）

`goodsInsight/sku/list` `requestType=1` 拉全量候选（含无资格），`requestType=80` 拉**当前真正有资格**的 SPU；
再批量 `bidding/suggest` + `cost/threshold`，产出表：
`SPU | 价格 | stars | 近30天销量 | 保障线 refundLimitPrice | 保底广告费率 1/refundLimitPrice | 每轮门槛 costThreshold | 门槛/价格 | 是否有资格`

### 用法 2：毛利率闸门（先筛掉「保亏」的品）

对每个 SPU 计算 `保底广告费率 = 1 / refundLimitPrice`，与商品毛利率比对：

- 毛利率 **>** 保底广告费率 → 值得投，赔付把它锁成确定性生意；
- 毛利率 **<** 保底广告费率 → 即使拿满赔付仍是亏损，只是亏损被封顶。**这类品不该因为「有稳赚资格」就投。**

### 用法 3：定价台阶扫描（真正的「提前验价」）

`suggest` 不接受自定义价格入参，服务端按商品现价计算。所以做法是：

1. 用店内同三级类目、不同价位的现有 SPU 做散点，拟合出该类目的「价格 → 保障线」台阶表（**零成本、不改价**）；
2. 找出卡在台阶下沿的商品（例：类目甲 40.8 的品，只差 1 元就能从 1.4 跳到 1.6）；
3. 小幅提价越过临界点后 **24h 内重跑接口复验**保障线是否真的跳档。

约束：提价不得压低价格星级（需 ≥3 星，`goodsInsight/sku/list` 的 `stars` 可监控），也不得违反活动/价保规则；改价属于商家决策，必须由用户确认后执行，Skill 不代改价。

### 用法 4：定向养资格队列

对**尚未达 533**的品，按 `refundLimitPrice` 高、`costThreshold/价格` 低排序，选 Top N 优先补足「近 30 天 5 单 + 3 好评」（走自然动销、站内活动、特价热卖/秒杀/超补等白皮书提到的频道；订单一律走真实成交——含真实付款收货的内部采购/测试单，不做虚假交易）。
提前知道哪个品将来保障线最高，就知道该先养哪个 —— 这是接口最不可替代的价值。

### 用法 5：每 7 天刷新哨兵

白皮书说建议值每 7 天刷新且达成目标有机会上调；后台每天只能改 3 次目标 ROI。
把 probe 设成周期任务，在刷新日第一时间读到新的 `refundLimitPrice` 并把目标 ROI 抬到新线，吃满阶梯复利。

### 用法 6：预算与门槛护栏（防止「设高 ROI 反而拿不到赔付」）

目标 ROI 设得高 → 系统压量 → 7 天消耗可能跑不过 `costThreshold` → **本轮零赔付**。这是平台的对冲机制。
执行规则：

- 日预算下限 ≈ `costThreshold / 7 × 2`（留足冗余）；日预算是上限不是消耗保证。
- 第 4 天检查累计消耗：若 `< costThreshold × 0.5`，当天下调目标 ROI 一档（用掉每日 3 次修改额度中的 1 次），优先保证过门槛。
- 计划连续开满 7 天以上，不暂停、不删除、不开一键起量、不挂自动化规则。
- 28 天周期结束后重新建计划，并在建计划前重跑一次 probe 取最新保障线。

## 五、采集接口与操作约束

`scripts/surewin-probe.js` 已封装下列调用（须 9224 店铺档浏览器已登录京准通）。
公共请求头：`loginMode: 0`、`siteId: 0`、`language: zh_CN`、`credentials: include`。

提前验价请求体（`POST https://atoms-api.jd.com/dspad/bidding/suggest?requestFrom=0`，2026-09 实测参数高度敏感，campaignType 必须 153、biddingTarget 16、automatedBiddingType 8192、suggestRouter 2，否则落普通建议分支不返回稳赚值）：

```json
{"businessType": 600000013, "campaignType": 153, "biddingTarget": 16,
 "automatedBiddingType": 8192, "suggestRouter": 2,
 "location": "jztwzHomePageBanner",
 "swaBiddingQueryList": [{"adGroupId": null, "sxuType": 1, "sxuId": "<SPUID>", "skuIds": null, "sureWinFlag": 1}]}
```

`sureWinFlag: 1` 走稳赚分支返回真实 cap+门槛；0/2 是普通分支（cap≈10 无效值）。**未获资格 SPU 同样可查 cap**——报名前即可预判毛利闸门。

- SPU 列表：`POST /goodsInsight/sku/list`（`requestType=1` 全量候选，`requestType=80` 当前有资格）。
- 建议与上限：`POST /dspad/bidding/suggest`，读 `swaBiddingSuggestList[]`。
- 每轮门槛：`POST /dspad/sure/win/spu/cost/threshold`，**必须带同一会话 suggest 返回的 `ext.traceId`**，不可复用旧值。

### 定价口径：一律按普惠到手价（2026-09-29 用户红线，实测）

- **所有 ROI、广告出价、点击成本的定价依据 = 「普惠到手价」（perfectArrivalPrice），禁止用京东价（jdPrice）。** 京东价只是展示价，会高估承受力（实测云仓主投 SKU：京东价 60.8 vs 到手 43.86，1.4 倍差距）。系统建议出价/推荐 ROI 是平台口径，不能直接抄。
- 实时查询入口：京麦 → 营销 → 促销工具 → 营销价格管理 `shop.jd.com/jdm/mkt/market/market-risk`；接口 `dsm.market.tool.common.api.PriceQueryOuterService.queryPriceInfoList`（页面上下文内 fetch 无需 h5st，见 SKILL.md §4c / `scripts/probe-arrival-price.js`）。到手价随促销变动，投放/调价前必查。
- 出价公式（用户确认）：**出价 ≤ 到手价 × 20% × 该词 CVR**（单均广告成本 = 出价÷CVR ≤ 到手价×20%）；低于 0.8 元起投下限的词删，不硬投。按此口径实测已删礼物类高价词（参考价 3.02–3.82 × 行业 CVR 4.19%，单均获客可达到手的数倍）。
- 到手价组成（用户纠正 2026-09-29，直接采信）：**官方直降与国补都不改京东价，均为支付端优惠**，只降前台到手价；**报名比例由各店商家按实际毛利率自定，不统一**。公式（15% 仅为示例）：直降=round(京东价×直降比例,2)；国补=round(京东价×(1−直降比例)×国补比例,2)；到手价=京东价−直降−国补（15%+15% 示例≈×72.25%）。估算时勿把直降当成改京东价，勿假设统一折扣率——验证实验记录实际比例与 probe-arrival-price 实测到手价。
- **stockNum 字段对 POP 店普遍失准**（五店实测全 0，包括实际有货、能正常创建计划的品）→ 库存读数一律降级为提醒项，以商家后台实际库存为准；0 库存也不阻塞稳赚资格授予。
- 注意：`costThreshold ≈ 5×京东价/cap` 是系统门槛公式的观察结论（系统按京东价算），与「我们自己定价用到手价」不冲突——前者是平台行为，后者是我们的出价纪律。

### cap 刷新机制（2026-09-28/29 实测，9-29 修正刷新节奏结论）

- **触发**：SPU 级真实成交数据。同店 15 SPU 中，当日有成交的 1 个 cap 变动、14 个零成交 SPU 全部不变；两店同晚各自验证。
- **节奏（2026-09-29 修正）**：非即时，但**不是固定「晚间批」**——9-29 21:00→22:25 直接观测到同日多轮日内刷新（Ai 2.8→2.6、吖嘟咪相机款 2.7→2.8、圣迪欧坐便器 4.0→3.7、圣迪欧零销量 SPU 7.3→5.6→5.4→5.1→4.4→4.1 连续多轮漂移，门槛恒 7 地板）。旧结论「晚间 18:00–20:30 批处理窗口」「cap 当天不刷新」**作废**。
- **【已验证-本地】对比纪律**：跨日比较必须**同日同时点对同时点**（如 21:00 vs 21:00），日内快照只作事件线索；当日要出归因结论必须配合实时订单+到手价快照（见归因流程节）。
- **方向（推断，待更多样本）**：由新证据相对旧锚点的质量决定，与订单数量无关——旧锚点 130 件×5.8 元甩卖的店，3 笔 31.8 元正价单当晚 +0.3（2.5→2.8）；旧先验含正价单的店，同买家连发 21 笔当晚微调 -0.1（2.9→2.8）。
- **门槛联动**：cap 变动当晚门槛同步反向变动，`costThreshold ≈ 5×京东价/cap` 两例均咬合。
- **模型侧批量重算（2026-09-29 归因案例，已验证）**：圣迪欧坐便器 4.0→3.7 已排除改价（92 SKU 到手价两次快照零变化）、新成交（当日 0 单）、广告操作（无任何计划）三因，同窗口两个零销量 SPU 联动下移、cap/退款上限/建议档全字段等比 ×0.925 缩放 → **模型侧重算可以让 cap 在无任何店铺动作时日内变动**，归因时不能默认「动了一定有原因在店里」。
- **操作含义**：① 当日要出归因结论（cap 为什么动）必须配合 `scripts/probe-orders.js` 查实时订单、`probe-arrival-price.js` 查到手价，商智 T+1 会误导；② 稳赚计划的成交养 cap 路径已被验证（真实正价成交 → cap 上移），但同买家连发大量单/集中爆发的批量单的边际效果可能为负（见补单纪律）；③ 目标投产比必须按当日实时验价填写（cap 会日内变），历史值不可复用。

### 资格授予机制（goodsInsight rt=80 推荐池，2026-09-29 五店实测）

- **资格可程序化读取，不必等弹窗**：`POST /goodsInsight/sku/list` 传 `requestType=80` = 「可新建稳赚推广」当前推荐池（就是弹窗的数据源）。返回条目字段：`spuId/spuName/saleVolumeStr/orderImproveCnt/saleTime/pvStr/wzOrderPreImprove/stars/recommendReason`，资格品带 `recommendReason:["稳赚"]`。`requestType=1` = 全量候选（含无资格），全量条目也有 `saleVolumeStr`（销量分档："0"/"小于100"/"100+"）。
- **五店规律（已验证）**：进入过 rt=80 的 SPU 全部满足 `saleVolumeStr="100+"` 且 `orderImproveCnt=15~16`（全店最高）；sale="0"/"小于100"（improve≤13）的 SPU 无一入池。
- **资格跟店级真实销量走，不跟商品本身走（同款跨店对照）**：同货同价相机款——销量 100+ 的店有资格、零销量的店同款无资格。
- **开稳赚 = 移出推荐池（已验证）**：创建单品稳赚后该 SPU 立即从 rt=80 与全量列表消失 → rt=80 是「未消费资格」池；监测资格用接口轮询，**弹窗不可靠**。
- **弹窗消失 ≠ 资格收回**：`sure/win/ht/campaign/check` 返回 `canPut=true` 即切换资格仍在（实测弹窗消失后仍 true）；弹窗疑为一次性展示/频控。
- **资格弹出与 cap 是两条管道**：资格授予时 cap/门槛纹丝不动（皮套/相机款实测）→ 资格弹出≠必须抢时间开。
- **库存不阻塞资格**：92 个 SKU 全部 stockNum=0 的 SPU 照样在 rt=80 池中（注意 market-risk stockNum 对 POP 店普遍失准，库存以商家后台为准）。
- **【推断，待验证】**：资格触发 ≈ 累计销量跨入 "100+" 档 + `orderImproveCnt` 足够高（15+），两因子共变未分离；授予节奏（日批/事件级）、未消费资格有效期未知。**确证实验**：选一个 "小于100" SPU 推过 100 档，每日 rt=80 快照看分档跳变与授予的时滞。

### cap/门槛变动归因流程（每次变动必走，2026-09-29 实战定型）

归因顺序（手册级纪律）：**先查改价 → 再查实时订单 → 再看品退**；对照组逻辑 = 零订单 SPU 应不动。

0. **协同投放排查**：先确认该店是否有采销 C+A 协同对投（比例对投/稳赚联投；cxjzt 后台只读核验，见 SKILL.md 4d）。协同加价产生的成交是真实成交、可能触发 cap 刷新（待验证），归因时须把协同单从「商家动作→成交」因果链中剥离；「稳赚联投」还会直接抬高指定稳赚品 ROI 上限，实验期间视为污染源。
1. **改价**：全店到手价快照对比（`probe-arrival-price.js`，两次读数逐 SKU 比对 jdPrice/arrivalPrice/perfectArrivalPrice/stockNum）。若 cap 与门槛**同向变动**，先怀疑改价——隐含价 = 门槛×cap/5，可与现价互验。**国补/直降不改京东价**（支付端优惠），按假设不应引发 cap/门槛变动（待验证）。
2. **实时成交**：`probe-orders.js` 查当日新订单（**商智 T+1 不能当实时证据**）。
3. **品退/售后**：核对变动 SPU 当日售后记录。
4. **全部排除 → 模型侧批量重算**：特征 = 同轮多个 SPU 联动变动、cap/refundLimitPrice/建议档全字段**等比缩放**、零销量 SPU 同步漂移而部分 SPU 纹丝不动。此时结论写「模型侧重算，非店铺动作触发」。

判读纪律：机制解释一律标【推断，待验证】；门槛公式只在中低客单价（10~90 元）吻合，高客单（338~614 元）不符，勿硬套。

### 补单与证据注入纪律（2026-09-29，用户口径）

稳赚/关键词计划的目的之一是给 SPU 注入转化证据养 cap。订单一律走真实成交（含真实付款收货的内部采购/测试单），质量要求：

- **不同买家账号、正价购买、每店少量**，不集中同一天同一账号；
- **分散时间、接近正常转化节奏**——集中爆发的批量单（如两分钟内 44 单）疑似「差证据」，可能把高 cap 拉下来（圣迪欧 4.0→3.7 归因案例的推断方向，待验证）；
- **最好经关键词广告位下单**：同时喂「SPU 成交」和「广告位 CVR」两类证据；
- **带图好评继续**（CVR + 稳赚资格门槛双受益）；
- 首日 0 订单属冷启动正常；若连投数日持续 0 转化，说明证据注入落空，应复盘词/落位而不是继续干等。
